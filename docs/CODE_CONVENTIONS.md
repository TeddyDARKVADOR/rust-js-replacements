# Code conventions

These rules apply to every package. Tooling enforces what it can (`rustfmt`, `clippy`, Biome,
TypeScript strict mode); reviews enforce the rest.

## General principles

- Everything is written in English: identifiers, comments, documentation, commit messages, and
  error messages.
- No emojis anywhere in the repository, including tests and fixtures. Test data that needs emoji
  or other non-ASCII characters uses escape sequences (`'\u{1F600}'` in TypeScript,
  `"\u{1F600}"` in Rust, `\uD83D\uDE00` in JSON).
- Prefer readable, maintainable code over clever code. Avoid abstractions that do not have at
  least two real uses.
- Do not duplicate code without a clear reason. When duplication is deliberate (for example, a
  JavaScript fallback that mirrors Rust logic), explain why in a comment.
- Keep functions focused and predictable. Avoid global mutable state unless strictly necessary.
- Use explicit types for public interfaces.
- Handle errors explicitly and never silently ignore them. When a fallback cannot happen in
  practice, document why at the fallback.
- Do not create files without a practical purpose, and do not add dependencies without checking
  that they are necessary.

## Rust

- Idiomatic modern Rust, edition 2024, the toolchain pinned in `rust-toolchain.toml`.
- `cargo fmt` formatting and `cargo clippy --all-targets -- -D warnings` with the workspace lints
  (`clippy::all` and `clippy::pedantic`). Exceptions use `#[allow(..., reason = "...")]` at the
  narrowest scope.
- Core crates use `#![forbid(unsafe_code)]`. Binding crates may contain unsafe code generated by
  NAPI-RS or wasm-bindgen; hand-written `unsafe` must be justified in a `// SAFETY:` comment.
- Use meaningful error types (`thiserror`-style enums when a crate has fallible operations). Never
  `unwrap` or `expect` on input-dependent values in library code.
- Avoid unnecessary allocations and copies: borrow (`&str`, `Cow`) when possible.
- Document every public item (`missing_docs` is enabled).
- The core crate never depends on Node.js, browsers, NAPI-RS, or wasm-bindgen.
- Reuse mature crates instead of rewriting algorithms (for example, `unicode-segmentation`).
- Generated code is marked `@generated`, states its generator, and is never edited by hand.

## TypeScript

- TypeScript in strict mode, plus `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
  `verbatimModuleSyntax`, and `erasableSyntaxOnly` (so that Node.js can run the sources directly).
- No `any` (enforced by Biome). Use `unknown` and narrow it.
- Accurate public type definitions, emitted by `tsc` from the sources.
- Keep the public API as close as possible to the original library. Additions (such as batch
  functions) are named exports.
- Use named exports; a default export exists only when the original library has one.
- ESM is the module format. CommonJS consumers are supported through `require(esm)` (Node.js
  22.12 and later); add a separate CommonJS build only if a package must support older runtimes.
- Node.js and browser entry points are separate files and separate `exports` conditions.
- Errors are thrown as built-in error types (`TypeError` for invalid arguments, `Error` otherwise)
  with an English message that says what to do.
- Formatting and linting use Biome (`pnpm run lint:js`).

## Naming

| Element | Rust | TypeScript |
| --- | --- | --- |
| Functions, variables | `snake_case` | `camelCase` |
| Types, structs, classes | `PascalCase` | `PascalCase` |
| Constants | `SCREAMING_SNAKE_CASE` | `UPPER_SNAKE_CASE` |
| Crates, npm packages, files | `kebab-case` crates, `snake_case.rs` files | `kebab-case` packages and files |

Crates of a package are named `<package>-core`, `<package>-node`, and `<package>-wasm`.

## Tests

- Every package has unit tests (Rust), API tests, and compatibility tests that compare the package
  with the original library running in the same process.
- When the original library has its own test suite and its license allows it, vendor it unchanged
  apart from the import (and escape sequences for non-ASCII characters), with the license next to
  it.
- Randomized tests are seeded so that failures are reproducible.

## Commits

- English, imperative mood, short summary line (for example, `Add batch API to string-width`).
- One logical change per commit.

## Quality gate

A package is complete only when all of these pass: compilation, formatting, linting, unit tests,
compatibility tests, a dependency audit without known critical issues, documentation, and
reproducible benchmarks.
